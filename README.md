# Kanban API

REST API for managing tasks on a Kanban board, built with Spring Boot using a hexagonal architecture (ports & adapters).

## Requirements

- Java 17
- Maven (optional: the project includes the Maven Wrapper `mvnw`)

## Running the application

**From the terminal**

Windows (PowerShell):

```powershell
.\mvnw.cmd spring-boot:run
```

macOS / Linux:

```bash
./mvnw spring-boot:run
```

**From IntelliJ**

Open `KanbanApiApplication.java` and click the green ▶ icon next to the `main` method.

The application is running once `Tomcat started on port 8095` appears in the console.
The base URL is:

```
http://localhost:8095
```

## Profiles and configuration

The configuration lives in `src/main/resources`:

| File                            | Contents                                                 |
|---------------------------------|----------------------------------------------------------|
| `application.properties`        | General settings (name, port, active profile)            |
| `application-h2.properties`     | H2 in-memory database, JPA/Hibernate and the H2 console  |
| `schema.sql`                    | Creates the database tables (see [Database schema](#database-schema)) |

The `h2` profile is active by default via `spring.profiles.active=h2`.
To choose the profile at startup yourself:

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=h2"
```

> **Note:** H2 runs in memory. The database is empty again after every restart of the application.

## Database schema

The tables are not generated by Hibernate; they are created by `src/main/resources/schema.sql`.
Spring runs this script at startup, which also fixes the order of the columns.

Hibernate is set to `spring.jpa.hibernate.ddl-auto=validate`: at startup, Hibernate checks
whether the tables match the JPA entities. If they don't, the application will not start.

> **Note:** when you add a field to `TaskEntity`, also add the column to `schema.sql`.

**Table `tasks`**

| Column        | Type                          | Required | Description                                    |
|---------------|-------------------------------|----------|------------------------------------------------|
| `id`          | `UUID`                        | yes      | Primary key                                    |
| `title`       | `VARCHAR(100)`                | yes      | Title of the task                              |
| `description` | `VARCHAR(500)`                | no       | Description of the task                        |
| `status`      | `VARCHAR(20)`                 | yes      | `TO_DO`, `IN_PROGRESS` or `DONE` (stored as text) |
| `created_at`  | `TIMESTAMP(6) WITH TIME ZONE` | yes      | Time of creation                               |
| `updated_at`  | `TIMESTAMP(6) WITH TIME ZONE` | yes      | Time of last update                            |

## Endpoints

| Method  | URL          | Description                |
|---------|--------------|----------------------------|
| `POST`  | `/api/tasks` | Create a new task          |

### Create a task

```
POST http://localhost:8095/api/tasks
Content-Type: application/json
```

**Request body**

| Field         | Type   | Required | Rules                                                       |
|---------------|--------|----------|-------------------------------------------------------------|
| `title`       | string | yes      | Not blank, max 100 characters                               |
| `description` | string | no       | Max 500 characters                                          |
| `status`      | string | no       | `TO_DO`, `IN_PROGRESS`, `DONE` or `To Do`, `In Progress`, `Done` (case-insensitive). Default: `TO_DO` |

**Example request**

```json
{
  "title": "First task",
  "description": "Test H2",
  "status": "TO_DO"
}
```

**Example response** - `201 Created`

The `Location` header contains the URL of the new task, for example
`http://localhost:8095/api/tasks/3f2b8c1e-5d4a-4e7b-9c1a-2b6d8e0f7a91`.

```json
{
  "id": "3f2b8c1e-5d4a-4e7b-9c1a-2b6d8e0f7a91",
  "title": "First task",
  "description": "Test H2",
  "status": "TO_DO",
  "createdAt": "2026-11-18T10:15:30.123456Z",
  "updatedAt": "2026-11-18T10:15:30.123456Z"
}
```

**Error responses**

Errors are handled by `ExceptionController` and returned as plain text.

| Status            | When                                      | Example body                                     |
|-------------------|-------------------------------------------|--------------------------------------------------|
| `400 Bad Request` | `title` is missing or blank               | `title: Title should not be empty`               |
| `400 Bad Request` | `title` is longer than 100 characters     | `title: Title can't exceed 100 characters`       |
| `400 Bad Request` | `description` is longer than 500 characters | `description: Description can't exceed 500 characters` |
| `400 Bad Request` | Unknown `status`                          | `Status [BUSY] unknown. Allowed values: TO_DO/To Do, IN_PROGRESS/In Progress, DONE/Done` |

When multiple fields are invalid, each error is on its own line.

**Testing with PowerShell**

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8095/api/tasks `
  -ContentType "application/json" `
  -Body '{"title":"First task","description":"Test H2","status":"TO_DO"}'
```

**Testing with curl**

```bash
curl -X POST http://localhost:8095/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"First task","description":"Test H2","status":"TO_DO"}'
```


## H2 console

The H2 console lets you inspect the contents of the in-memory database.

1. Start the application.
2. Go to **http://localhost:8095/h2-console**
3. Fill in the login screen:

   | Field        | Value                   |
   |--------------|-------------------------|
   | Driver Class | `org.h2.Driver`         |
   | JDBC URL     | `jdbc:h2:mem:kanbandb`  |
   | User Name    | `sa`                    |
   | Password     | *(leave empty)*         |

4. Click **Connect** and run, for example:

   ```sql
   SELECT * FROM TASKS;
   ```

> **Note:** replace the default JDBC URL (`jdbc:h2:~/test`) with `jdbc:h2:mem:kanbandb`. Otherwise H2 creates a new, empty database and you won't see the `TASKS` table.
